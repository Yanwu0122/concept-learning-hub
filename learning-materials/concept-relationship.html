概念关系：上下文 · Agent · Skill
三个核心概念的关联与协同
三者概览
大模型的上下文
模型的"工作记忆区间"，承载每一次推理所依赖的全部输入信息，是能力发挥的基础边界。
Agent（智能代理）
在上下文之上运转的"行动者"，负责感知、推理、调用工具并执行任务。
Skill（技能包）
沉淀下来的"能力资产"，把流程与知识封装起来，供 Agent 按需加载复用。
它们如何关联
1. 上下文是 Agent 的"工作台"
Agent 的一切推理都发生在大模型的上下文窗口中。上下文里放入多少、什么质量的指令与资料，直接决定 Agent 能否作出准确判断。可以说，上下文是 Agent 思考与行动所依赖的临时信息空间。
2. Agent 是上下文的"使用者与组织者"
Agent 负责把任务相关的内容（检索结果、历史、系统提示、用户输入）合理地组织进上下文，驱动模型完成推理，并据此调用工具、执行动作。它像一位在有限工作台上调度资源的统筹者。
3. Skill 是 Agent 可复用的"方法库"
Skill 把"完成某类任务的最佳流程与知识"提前封装。Agent 识别到任务匹配时把 Skill 的内容（含脚本与参考）加载进上下文执行，从而复用经验、减少每次从零摸索的成本。
协同工作示意
用户提问 → Agent 加载 Skill → 组织进上下文 → 模型推理 → 调用工具/输出
典型流程解读
当用户提出某个任务，Agent 先判断是否有匹配的 Skill；若有，则把 Skill 的指南、可能的脚本说明一并纳入上下文；随后在有限的上下文窗口内完成推理规划并执行。Skill 让"怎么做"沉淀下来（降低每次的探索成本），上下文则决定"这一次具体怎么做"。二者与 Agent 的思考与行动环环相扣。
关系总结

一句话概括：上下文是大模型的"信息工作区"，Agent 是使用该工作区自主行动的"执行者"，Skill 则是能让执行者少走弯路的"经验与流程库"。三者彼此依赖：Agent 在上下文中思考，通过加载 Skill 提升行动质量，而 Skill 的价值最终也要借助 Agent 的合理组织（放入恰当的上下文）才能发挥。强大的 Agent = 恰当的上下文 + 可复用的 Skill。
