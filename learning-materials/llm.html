LLM大语言模型（Large Language Model）
在海量文本上训练出的「接续生成器」，也是 Agent 时代的「大脑」
学习目标
  • 能用自己的话解释 LLM 是什么，以及它为什么是「概率生成器」而不是「知识库」
  • 能讲清 LLM 的完整链路：Token → Transformer/自注意力 → 预训练 → 指令微调 → RLHF 对齐
  • 能识别 LLM 的能力边界（幻觉、上下文窗口、知识截止），并说明 Agent 类应用如何绕开这些边界
  • 能结合 llm-wiki-agent 案例，说明「LLM + 流程 + 工具」如何组成一个自动维护的知识库 Agent
LLM 的「智能」到底来自哪里？它是在思考，还是在续写？
它为什么会一本正经地答错？幻觉与上下文窗口分别限制了什么？
从「聊天」到「干活」（例如 llm-wiki-agent 自动建 wiki），中间到底加了什么？
概念解释
我的理解：LLM 本质上是一个巨大的「下一词预测器」。它把人类积累的海量文本压缩进上千亿个参数里，学到的不是查字典，而是「接着最像的下文写」。它没有数据库、也不校验事实，但因为见过的模式足够多，涌现出了翻译、总结、推理甚至拆解任务的能力。所以正确的使用姿势是：把它当成一个极其博学、却会一本正经胡说的「实习生」——能力强，但需要给它资料、流程和检查，而这正是 Skill 与 Agent 要补上的部分。
Token 化：把文本切成模型认识的单位
模型不读字母和单词，而是把文本切成 token（约等于词或词根，如 walking 可拆成 walk+ing）。模型对 token 做预测，因此上下文窗口也以 token 计量——中文约 1 个汉字 ≈ 1~2 个 token。
Transformer 与自注意力：看见整段话的关系
2017 年《Attention Is All You Need》提出 Transformer。自注意力让每个 token 同时「观察」序列中所有其他 token，计算谁和谁相关，从而捕捉长距离依赖（例如把隔了很多句的「它」指回正确的名词）。它还能整段并行处理，让超大模型训练成为可能。
预训练：自己教自己的自监督学习
把互联网级的语料（网页、书籍、代码）喂给模型，目标只有一个：预测下一个 token。猜错了就调整参数。由于语料本身就是答案，不需要人工标注；语料和参数越大，能力越强，这就是「规模定律」。
指令微调 + RLHF：从「会续写」到「会听话」
预训练出的模型只会接着写。先用人工写的「问题-优质回答」对做监督微调（SFT），教它像助手一样回应；再用 RLHF（基于人类偏好的强化学习）让模型学会输出人类更喜欢、更安全的内容。ChatGPT/Claude 这类产品体验来自这一层。
推理时的上下文窗口与采样
生成时模型一次只能「看到」上下文窗口内的内容（从早期 4K token 到如今的百万级），窗口之外一律不记得。每次输出一个 token 前按概率采样，temperature/top-p 控制随机性。知识截止、幻觉都与这层机制直接相关。
涌现能力：规模带来的意外之喜
模型大到一定程度后，会出现少样本学习、思维链推理等未显式训练的能力。学界对「涌现」的界定仍有争议（部分取决于评测方式），但多步推理等能力确实更多出现在大模型上。
提示即接口：零样本/少样本适应多任务，无需为每个任务重新训练 优化「像不像」，不校验「对不对」——幻觉的根源 无内置记忆：只认当前上下文窗口内的信息 能力随规模涌现：大数据 + 大参数 → 强泛化 训练与推理算力门槛高，环境与资金代价大
应用场景
llm-wiki-agent：让 LLM 当你的知识库管理员
llm-wiki-agent 是 SamurAIGPT 开源的项目，定位是「会自动构建并维护自己的个人知识库」。用法很简单：把 PDF、论文、网页或笔记丢进 raw/ 目录，对编码 Agent 说一句「ingest 某文件」，Agent 就会读取文档、抽取其中的实体与概念，自动生成带 [[wikilinks]] 互相引用的 wiki/ 目录（含 index.md 目录页、log.md 操作日志、overview.md 总览、sources/ 来源页、entities/ 实体页、concepts/ 概念页、syntheses/ 查询沉淀页），还能生成可视化关系图谱 graph.html，并在发现资料间矛盾时当场标记。
把它拆开看，正好演示了 LLM 的三种能力如何组合成 Agent 工作流：1）阅读理解与信息抽取——把非结构化文档变成结构化的互链 wiki 页面；2）遵循 schema 执行流程——项目里的 CLAUDE.md/AGENTS.md 相当于「给 LLM 的岗位手册」，约束页面格式、命名与维护流程，这与本仓库 Skill 的思想一脉相承；3）把一次性问答沉淀为长期资产——query 的答案可以回存为 synthesis 页面，让每次投入都累积。项目还刻意区分于 RAG：RAG 每次查询现算现答，它则把知识「编译」成常驻 wiki、随每次 ingest 变厚。它的局限同样来自 LLM 本体——抽取可能出错，所以要有 lint 与人工抽查兜底，这恰好印证：LLM 需要「流程 + 检查」才能真正可靠。
概念辨析
LLM 是「会思考的电脑」还是「会查资料的搜索引擎」？
都不是。搜索引擎返回真实存在的页面，LLM 是逐 token 生成「最可能的下一段文字」，没有真值校验。它看起来懂很多，是因为训练语料里的模式够多；「说得流畅」不等于「说得正确」——这正是幻觉产生的原因，也是所有 LLM 应用必须做事实核验的理由。
LLM 和「大模型的上下文」（本仓库 llm-context.html）是一回事吗？
不是同一层的东西。LLM 是训练出来的模型本体（能力层）；上下文是推理时模型能看到的输入窗口（使用层），包括系统提示、对话历史、检索结果等。同一个模型，上下文里装什么、装多少，直接决定它答什么——LLM 决定「能答多好」，上下文决定「这次答什么」。
LLM Agent（如 llm-wiki-agent）和聊天机器人有什么区别？
聊天机器人一问一答，输出完就结束。Agent = LLM + 目标拆解 + 工具调用 + 多轮反馈：它能自己规划步骤、调用搜索/文件工具、根据结果修正，并把产出固化下来（llm-wiki-agent 把成果写成 wiki 文件就是「从对话到资产」）。若再把固定流程沉淀成 Skill，Agent 就能稳定复用地干同一类活。
自测检验
用一句话分别说明 LLM 训练三阶段解决什么问题。
预训练学语言模式（会续写），指令微调学「像助手一样回应」（会听话），RLHF 学人类偏好（更安全、更有用、少胡来）。
为什么把参考资料写进提示词能让 LLM 少幻觉？这利用了它的什么机制？
利用了上下文窗口机制：放进窗口的信息成为模型「当下可见」的续写依据，它会优先顺着给定材料组织输出，而不是全靠训练记忆中的统计联想编造。RAG 和 llm-wiki-agent 的 ingest 本质上都是把「外部事实」搬进上下文可见的范围内。
相比「把 PDF 直接丢给 RAG 问答」，llm-wiki-agent 的价值差异在哪里？
RAG 每次查询都临时检索拼接、答完即弃，不沉淀结构；llm-wiki-agent 把知识「编译」成常驻的互链 wiki，跨文档矛盾在 ingest 时就被标记，知识随每次投入持续累积，还能生成关系图谱。代价是它需要额外的流程约定（schema、lint）来保证质量。
