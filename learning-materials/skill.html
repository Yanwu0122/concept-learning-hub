封装特定专业知识、工作流程与工具的能力扩展包，供智能体按需加载执行

概念解释
Skill 是一个"能力扩展包"：把特定领域的知识、标准流程、参考文档和可执行脚本打包成一组文件，由智能体在遇到对应任务时按需加载并执行。它不像独立应用那样常驻运行，而是在智能体会话中被动态读取——智能体依据其中的 SKILL.md 指南决定怎么做，必要时调用脚本、参考文档，从而把抽象的"能力"沉淀成可复用的具体流程。
SKILL.md（入口与指南）
Skill 的核心线索文件，顶部用 YAML 描述名称与适用场景（description），正文给出任务目标、操作步骤、使用示例与资源索引。智能体通过它来判断"何时该用、怎么用"。
scripts（可执行脚本）
封装确定性的技术处理：文件格式转换、外部 API 调用、复杂计算、页面生成等。通常是带命令行入口的独立脚本，智能体按需以 `python scripts/xxx.py --arg value` 方式调用。
references（参考文档）
存放长规则、格式规范、领域知识等细节，避免全部塞进 SKILL.md。智能体在需要细节时才读取，保持上下文精简。
渐进式加载机制
智能体先看到 Skill 的名称与简短描述，判断任务匹配后再加载完整指南，进而按需调用脚本或参考文档。这保证了"只在必要时使用资源"，节省上下文。

应用场景
企业内部"客户画像生成"Skill
一家公司把"如何从 CRM 数据生成客户画像"沉淀为一个 Skill，存放了数据清洗规范、画像模板和生成脚本。业务人员对助手说"帮我看下这位客户"时，助手识别到匹配场景，自动加载该 Skill，按其流程拉取数据、调用脚本生成结构化画像，并套用统一模板输出。
这个场景凸显了 Skill 的价值：把分散在文档里的经验（数据规则、格式规范）和代码固化成一个统一入口，任何开发者或智能体都能复用它，"个人经验"由此变成"团队可复用的能力资产"。同时 Skill 不常驻、按需加载，避免给每次对话增加不必要的负担。
概念辨析
Skill 和插件（Plugin）有何区别？
插件通常指对外部系统/API 的接入封装，偏"连接外部服务"。Skill 范围更广，既可能包含脚本/工具，也可能只是纯流程与方法论（用文本指导智能体完成分析、写作等）。Skill 强调把"怎么做好一件事"的整体流程与知识沉淀下来。
Skill 是独立应用吗？它是否有独立界面？
不是。Skill 没有 main 入口、没有服务端口、没有 GUI，也不作为独立程序常驻。它依赖智能体在会话上下文中读取并执行。可以说 Skill 是"给智能体的能力包"，而不是"给用户的 App"。
自测检验
一个标准 Skill 目录中最核心的文件是哪个？它有哪些作用？
是 SKILL.md。它以 YAML 前言区描述 name 和 description，帮助智能体判断适用场景；正文提供任务目标、操作步骤、使用示例和资源索引，指导智能体如何完成对应任务并知道何时去读脚本或参考文档。
为什么 Skill 能被"复用"于不同项目？
因为 Skill 把领域知识与标准流程封装成独立目录，不依赖特定对话内容。只要智能体识别到任务匹配其 description 描述的适用场景，就能加载同一套流程和脚本，因此同一份 Skill 可服务于不同项目、不同次对话。
